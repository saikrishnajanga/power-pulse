1. Purpose of This Document
This document tells the people who run these models what to look after, what to watch, and what 
can go wrong. It covers routine maintenance, ongoing monitoring, a risk register based on what 
the notebook code actually does, and a response guide for common problems.

3.2 Retraining triggers
•
Rolling forecast error is clearly above the baseline set at the last accepted run (see section 
4).
•
A change in the household: new appliance, occupancy change, solar or battery installation, 
tariff change.
•
A gap or fault in the meter data that was later corrected.
•
A seasonal change not yet represented in the training data. Model A only learns months it 
has seen.
•
Library upgrades that change model behaviour.
3.3 Run steps: Model A
•
Confirm hourly_power_consumption.csv is in MyDrive/Electricity_consumption with 
Datetime and Hourly_energy_kWh.
•
Mount Drive and run cells in order. Cell 3 stops with an error if the file or columns are 
missing.
•
Check the printed row count and date range for sense before trusting any output.
•
Compare Cell 7 metrics with the baseline. Open the Cell 8 plot to confirm predictions follow 
actuals.
•
Confirm all four CSV files were written in Cell 13 and archive them.
3.4 Run steps: Model B
•
Place the house CSV files in ./REFIT and set DATA_PATH and OUTPUT_PATH.
•
Check the Step 8 log: houses skipped for a missing mapping, loading failures and training 
failures are printed, not raised.
•
Review the number of houses processed against the number of files supplied.
•
Review summary_table.csv and the statistics block; archive both CSV files.
